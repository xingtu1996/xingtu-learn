# 01｜最小实践：用 FDE 交付门禁验证 Semantica 是否值得引入

## 假设

H0：在单业务、规则明确、仅 6 条记录的规模下，**JSON + Python 规则足够**；引入图谱只是额外复杂性。

H1：在多跳关系、跨系统概念、历史版本冲突和决策追踪出现时，图谱/语义层提供显著的额外能力（必须实际测）。

本实验不是“证明 Semantica 一定好”，而是证明何时不需要、何时需要。

## 文件

- `data/requirements.json`：6 条虚构变更记录，包含审批时间、测试状态和伪造来源 ID。
- `run_baseline.py`：标准库基线，先判定 allow/block 与理由。
- `run_semantica.py`：把同一事实组织为图节点/关系，记录基线决策并进行 JSON 持久化恢复。
- `02-评测记录模板.md`：留空数据，禁止编造测量值。

## 六个基础用例

| 需求 | 情况 | 期望 | 需要识别 |
|---|---|---|---|
| R-001 | 审批与测试通过 | allow | 正常放行 |
| R-002 | 审批 pending | block | 缺少有效审批 |
| R-003 | 测试 failed | block | 测试不通过 |
| R-004 | 审批在预定发布之后 | block | 时序不符合 |
| R-005 | 审批未带 source_id | block | 缺少来源 |
| R-006 | approved 与 rejected 同时出现 | block | 事实冲突 |

**警告**：`source_id` 在本实验里是合成标签，不能证明真实系统确实批准；后续需要可信 API、身份签名、时间戳和不可篡改记录验证。

## 1. Semantica 单进程图实验

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install semantica
python -c "import semantica; print(semantica.__version__)"
python run_semantica.py
```

这段脚本依据官方 [ContextGraph API](https://docs.getsemantica.ai/reference/context/) 使用：
- `add_node` / `add_edge`：表达要求、审批、测试和发布的关系；
- `record_decision`：将基线规则结论写为可查询决策节点；
- `save_to_file` / `load_from_file`：保存和恢复图谱；
- `stats` / `find_node`：核验恢复。

**注意**：这不是 Semantica 的内置规则引擎验证。`run_semantica.py` 仍调用 `run_baseline.py` 中的规则函数，然后把结果记录为图谱决策。要证明 Semantica 的规则推理有额外价值，必须另做独立的 Semantica `reasoning` / `ontology` / `PolicyEngine` 实验，不可以把本脚本结果冒充“Semantica 自动审计”。

运行后应生成本地 `output/context_graph.json`（不要上传包含真实数据的产物）。如果 API 变化报错，记录完整错误、版本和复现步骤，而不是猜测“已通过”。

## 2. 三组关键对照实验

### A. 简单条件判断
- 固定 6 条同一数据，比较标准库与 Semantica 建图+记录决策的**额外耗时、内存、可维护性**。
- 若仅做 allow/block 判定，预期简单脚本有成本优势；不是已验证结果。

### B. 多跳关系/源定位
- 给每条需求补充 PR、测试、审批、发布记录及来源。
- 分别回答：哪些发布依赖一条已撤销审批？一个测试失败影响哪些需求？两个不同来源是否把同一实体识别为同一个？
- 比较 SQL/脚本 JOIN 维护复杂度、图遍历准确率、来源链是否可解释。

### C. 时序与冲突
- 使用冲突审批、审批晚于发布、证据缺失，记录“阻断”和具体证据。
- 设计一个来源 ID 有值但审批实际上无效的反例，验证系统**不会把存在记录当作有效授权**。
- 扩展为事实版本、撤销与恢复时，另加规则及回归测试。

## 4. 结果判定

- H0 成立且 H1 未证实：保留 Markdown/JSON/脚本，不引入常驻服务。
- 仅多跳/决策链获得提升：保留图谱派生索引，仍不替换原文仓。
- 语义约束、来源追踪、时序冲突都通过并可重建：考虑为 FDE/Harness 引入独立试验服务。
- 不论哪种情况，**未实际运行验证前本目录一律标「待实测」**。
