# 03｜行途专题：从个人知识管理到 AI 可执行知识

## 推荐专题名

**《从 Obsidian 到 Context Graph：AI 时代，知识为什么需要可计算？》**

副标题方向：一次 Semantica 实验，讨论知识梳理、语义治理、决策追溯与 AI 工程化的边界。

## 读者最关心的三个问题

1. 个人已经用 Markdown/Obsidian/知识库，为什么还会有人研究本体论、知识图谱？
2. 企业已经做了数据资产目录和治理平台，为什么“客户”与“审批”的业务语义仍然不清楚？
3. 上线 Agent 后，如何证明一次发布不是由一句口头“改吧”绕过审批？仅有审计日志够不够？

## 文章论证路线

1. **从真实问题切入**：同一需求跨文档、PR、审批、CI 测试与发布记录，人可读，但机器难以稳定核验。
2. **区分概念**：梳理回答“有什么”，数据治理回答“是否可管理”，语义治理回答“这意味着什么”，决策治理回答“为何这样做”。
3. **不用工具先解决**：最少 6 条合成数据，用 JSON + Python 检查发布规则，证明“没有工具也能治理”的边界。
4. **再引入 Semantica**：关系建模、决策节点、来源 ID、持久化，展示新增能力和额外成本，不强行宣称“高大上”。
5. **讨论商业价值**：FDE 交付模板、行业本体、审计证据链；核心是减少重复集成与人工追溯成本。
6. **反例与限制**：图中存在审批节点，不代表真实审批有效；遵循开放标准也不等于天然合规。
7. **结束于选型方法**：何时继续用 Markdown/SQL/Python，何时值得引入语义中间层。

- 公众号：一篇主文 + 对照实验的 GitHub 链接。封面展示文档、关系、规则、证据之间的层次，不重复文章标题。
