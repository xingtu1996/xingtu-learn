# 开源合规一页检查表｜个人 / 团队 / 公司 / 安全升级

> 2026-11-03 · v0.1 · 审核模板，不是法律认证。**任一权利来源不明、许可冲突或疑似敏感泄漏时，暂停公开发布。** 对公司项目请由有权限的法务、采购、信息安全和工程责任人审查。

[专题首页](README.md) · [行途案例](CASEBOOK.md)

## A. 发布自己的开源项目（Public Repo）

- [ ] **权属**：原创代码、文档、图像、字体、商标分别标明所有人；若受雇、委托、合作开发，查合同、岗位、公司资源和公开批准。
- [ ] **范围**：本仓是可修改/可再分发的开源软件，还是仅公开浏览的源码/知识？不把“Public”当授权。
- [ ] **LICENSE**：实际文件存在且内容有效；SPDX 标识、README 文案、徽章、文件头一致；第三方代码另列。
- [ ] **例外**：独立图片、数据集、模型权重、文章、品牌标志、API 和第三方内容已声明不同授权或不得再分发。
- [ ] **入口**：中文 `README.md` 为默认；英文 `README.en.md` 可返回；用途、运行、限制与当前验证状态可理解。
- [ ] **安全**：当前文件、Git 历史、提交元数据、二进制、部署面无未经批准的个人/客户/工作资料；密钥绝不提交。
- [ ] **工程**：安装/测试命令经过实际运行；CI、权限和发布步骤可复核；未测明确写 `NOT_RUN`。
- [ ] **治理**：`CONTRIBUTING`、`SECURITY`、Issue/PR 模板根据风险适度设置，不能填入无法保障的安全承诺。
- [ ] **发布**：审批人确认许可与公开授权；发布前核对最终 commit SHA；上线后抽检访问地址与下载包。

## B. 接收别人贡献的代码（Team PR）

- [ ] 贡献者有授权；员工/外包贡献按各自公司的 IP 及开源贡献政策审查。
- [ ] DCO 的 Signed-off-by 与 CLA 的额外协议区别清楚；仓库选择了明确的一条贡献路径。
- [ ] 新增依赖与文件分别有来源、版本、许可证、版权声明和 NOTICE 义务。
- [ ] 许可证变化、反向引用、第三方截图或模型权重变化由指定 Reviewer 审查。
- [ ] PR 记录影响文件、测试、回退、隐私检查、许可证决策；不以“mergeable=true”代替完整验收。

## C. 公司使用第三方开源（采购/研发/法务/安全）

- [ ] **入口登记**：组件与传递依赖、版本、下载源、Hash、所属产品/团队、用途及 Owner。
- [ ] **使用方式**：内部执行、客户交付、容器/SDK 分发、SaaS 服务分别记录。
- [ ] **兼容审查**：MIT/Apache/MPL/LGPL/GPL/AGPL/CC/商业授权与实际使用方式匹配；未获得确认的组合升级人工/法务审查。
- [ ] **授权履约**：`LICENSE` / `NOTICE`、版权声明、修改记录、可能的源代码提供义务落实到**发布包**，不只在代码仓。
- [ ] **供应链**：SBOM、依赖变更审查、供应商/源码完整性、漏洞与恶意软件风险记录。
- [ ] **企业治理**：职责分工、例外批准、供应商合同、审计留痕、教育培训、持续复核机制。
- [ ] **交付验收**：版本、二进制、对应源码和文档匹配；法务、安全及产品 Owner 对需授权事项留证。

## D. 安全升级（每个高风险补丁 PR）

- [ ] 关联 GHSA/CVE/上游安全通告，明确漏洞是否影响**实际运行环境**。
- [ ] 记录旧版/候选新版、影响与破坏性变化、依赖链、安全严重度及确认状态。
- [ ] 复核新版本的许可证、来源、NOTICE 和分发方式，防止“修了漏洞，改坏授权”。
- [ ] 具备测试矩阵、必要的兼容性验证和补丁部署/回滚方案。
- [ ] 确认生产升级审批、风险窗口和责任人；禁止测试失败或授权不明时自动发布。
- [ ] 结束后回填构建 SHA、验证记录、部署证据、监控效果以及剩余风险。

## E. 判定与回退

| 结论 | 最小条件 | 动作 |
|---|---|---|
| **可按当前许可继续开发** | 权属明确、许可一致、风险受控、未涉及发布 | 保留证据，按正常 PR 流程 |
| **可进入公开审核** | 公开面隐私与权属已核对、内容完整、测试执行结果真实 | Draft → 独立审查；仍需合并和发布权限 |
| **需法务/安全批准** | GPL/AGPL 兼容性、专利、公司职务作品、客户分发、数据等边界未明确 | 维持 Draft，记录问题和责任人 |
| **禁止公开 / 必须返工** | 权属不明、许可证互相矛盾、泄露私密信息、未获许可复制素材、严重漏洞未处置 | 阻断对外发布；隔离、修复、再审核 |

### PR 评论复制模板

```markdown
## 开源许可与安全审查
- 仓库 / PR / 目标 SHA：
- 作品权属：已核实 / 未知 / 需授权
- 使用方式：内部 / 分发 / SaaS / 公开源码
- 许可证：根 LICENSE / README / 文件头 / 依赖实际结论
- 第三方来源与 NOTICE / 源代码义务：
- 个人/客户/企业资料及历史扫描：
- SBOM/依赖/漏洞变化：
- 实际执行命令与结果（不执行写 NOT_RUN）：
- 决策：可进入审核 / 待法务或安全批准 / 禁止公开
- 风险、责任人、下一步、回退：
```
