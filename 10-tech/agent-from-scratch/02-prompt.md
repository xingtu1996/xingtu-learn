# 02 · 提示词：从一句话到 ReAct

## ① 这一层解决什么问题

地基（01）解决「上下文里有什么」，这一层解决「上下文开头那段话怎么写，以及模型按什么节奏思考」。

为什么需要专门的提示词？因为只把用户输入丢进去，模型不知道自己是谁、不该碰什么，也不会自发地多步推理。所以提示词分两件事：一是任务约束（我是谁、场景是什么、什么不能做），二是推理模式（ReAct：观察 → 思考 → 行动 → 观察）。

任务约束对应郭美青（百川）在现场讲的 HE 六层里的「任务约束层 / 身份纪律」——这是 Agent 的边框，没边框模型会跑偏。ReAct 则是让模型在循环里一步步走：先观察上下文，再决定下一步调哪个工具，执行完把结果接回来，再观察。没有这个节奏，V3 的 while 循环只是空转。

## ② 最小代码：五版进化 + ReAct 骨架

```python
# V1 两行：只有一句用户输入，无推理
ctx = system_prompt + user_input
reply = model(ctx)

# V2 五行：加工具协议，但仍是单轮
ctx = system_prompt + user_input + tool_protocol + tool_set
req = model(ctx)
if req.is_tool_call:
    ctx = append_context(ctx, run_tool(req))
    reply = model(ctx)

# V3 while True：模型按 ReAct 节奏反复走
ctx = system_prompt + user_input + tool_protocol + tool_set
while True:
    step = model(ctx)                       # 观察 + 思考
    if step.is_final_answer:                # 出口判断
        break
    ctx = append_context(ctx, run_tool(step))   # 行动 + 观察结果回写
print(ctx.final_answer)

# V4 工具协议：只放名称/解决什么/输入（详见 03-tools）
# V5 skill_catalog：Skill 也变成可查询协议（详见 04-loop）
```

ReAct 不是新代码，是写进 system_prompt 的推理约定：每轮先输出「我看到了什么 / 我下一步要做什么 / 调哪个工具」，程序解析后再把结果喂回去。模型因此学会了「想一步、做一步、再看一步」。

## ④ 我的理解

ReAct 我之前就知道，新的是把它和「任务约束层」钉在一起看：推理模式解决「怎么想」，约束层解决「在什么范围内想」。我上午场先想到的「除模型外皆 Harness」，在这里找到了下半截——系统提示的约束、ReAct 的节奏、结果的回写，全是 Harness，目的只有一个：把模型控制在该控制的地方。

我过去容易把提示词当成「写好一段话让模型听话」，现在更清楚：它是 Agent 的边框加操作系统的引导扇区，缺了边框，循环跑得越欢越容易出界。

## ⑤ 可复用产物：任务约束式 System Prompt 模板

```
你是 {角色}，只服务于 {场景}。
你只能做：{允许的能力清单}。
你绝不做：{明确禁区，例如擅自发消息给客户、编造数据}。
遇到不确定时：先调用工具核实，不要凭空回答。
每轮按 ReAct 输出：观察 / 下一步 / 工具调用。
```

把花括号填实，就是 V1/V3 里那段 `system_prompt` 的骨架。
