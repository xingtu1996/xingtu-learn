# 从零点亮一个 Agent

这条线记录我怎么把「Agent」从一个飘在空中的词，变成一段能跑通思路的代码。源头是 PEC2026 大会梁凯锐（词元映射 tokenmap CTO）那场「点亮第一个 Agent」的现场演示，他用一条进化链讲完了 Agent 的始末：ReAct → 两行代码 → 五行 → while 循环 → 工具协议 → Skill 渐进式加载。我把这条链拆成 4 个阶段，每个阶段配一段最小伪代码，跟着走就能在脑子里点亮自己的第一个 Agent。

## 为什么要学这条线

Agent 这个概念现在满天飞，框架也一堆（LangChain、CrewAI、OpenAI Agents SDK……）。但很多文章要么停在「它是个会调工具的 LLM」，要么一上来就丢一套框架让你抄。结果就是你以为懂了，合上网页还是拼不出一条完整的链：模型怎么拿到工具、什么时候停、Skill 又是怎么进上下文的。

我自己的痛点也一样：之前能说出 ReAct，能说出「给模型挂工具」，但说不清「两行代码为什么不行、加上 while 之后决策权怎么就从程序挪到了模型」。这场分享的价值，就是它用五版递进的代码把这件事从地基讲到楼顶，一步不跳。所以这条线不追新框架，只追那条不变的主链。

## 学习路径

| 阶段 | 对应文件 | 学完能做什么 |
|---|---|---|
| 一 · 地基：上下文 | 01-context.md | 写出 V1/V2，讲清为什么只拼上下文的 chatbot 做不了真实任务，以及 append_context 为什么是心脏 |
| 二 · 提示与推理：从一句话到 ReAct | 02-prompt.md | 写出任务约束式 System Prompt，讲清 ReAct 四步（观察/思考/行动/观察） |

| 四 · 循环与加载：while + Skill 渐进加载 | 04-loop.md | 写出 while 循环让决策权归模型，再用 search/load_skill 实现几百个 Skill 的按需加载 |

## 当前进度

诚实说：刚听完现场，正在消化。

前四篇的伪代码是我按现场演示**重建**的，能讲清思路，但那是我的理解，不是作者的原文。写完之后我找到了讲者开源的完整仓库（九幕、6434 行 Python、MIT），读完发现真实顺序和我拆的不一样——**while 循环在第 02 幕就出现了，远早于 System Prompt 和工具协议**，而且多出 RAG、完整交付、五个实战场景三块我完全没有的内容。对照记录写在 [05-source-code-map.md](05-source-code-map.md)。

真实源码以作者的仓库为准，本目录下的代码只当学习笔记看。Skill 渐进加载那段我还没在自己环境里验证过 token 节省的实际量级。
