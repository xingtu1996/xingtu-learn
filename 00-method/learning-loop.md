# 我的学习循环

> status: 活跃 ｜ 建立: 2026-09-13 ｜ 已验证场景: 考证备考（PMP 2023 通关）、新技术学习（Agent 2026-09 起步）
> 读者能拿走什么：一套六步学习循环 + 每步的可执行动作 + 防断档机制。照着改，就是你的学习系统。

---

## 为什么需要一个循环

学习最大的敌人不是难，是**断**。

难的东西咬咬牙能啃下来，断掉的东西却回不来——因为重新开始的心理成本比继续高十倍。我见过太多「学了两周，停了三天，然后再也没打开过」的计划，包括我自己早年的几次。

所以这套循环的设计目标只有一个：**让「继续」比「放弃」更容易**。

---

## 六步循环

```
计划 → 输入 → 笔记 → 产物 → 复盘 → 沉淀
  ↑                                    │
  └──────────── 回到计划 ──────────────┘
```

### 1. 计划：先写「学完能做什么」，不写「学什么」

反例：「这周学 Agent」。这不是计划，是愿望。

正例：「这周结束后，我能用 20 行 Python 跑通一个能调工具的 while 循环」。

判定标准：**能不能被外人验证**。能演示、能跑、能讲给别人听的，才是目标；「我理解了」不算。

### 2. 输入：一次只开一个源，且先要骨架

信息源开太多是学习最大的陷阱——每篇都看了，每篇都没消化。

我的做法：

- **一次只跟一个主源**（一本书 / 一门课 / 一位讲者）
- **先要骨架再补细节**：先搞懂这件事的整体链路是什么，再往里填细节。反过来（先学细节再拼骨架）是我踩过最多次的坑——细节记了一堆，拼不成一条链，等于没学。
- 我的笔记里会标 `[我此前已知]` / `[新学的]` / `[待核实]`，避免把旧认知当成新收获。

### 3. 笔记：只记「我的话」，不抄原文

抄原文是最舒服也最没用的动作——手在动，脑子没动。

规则：

- 一段内容，合上原文，用自己的话写一遍。写不出来的地方，就是没懂的地方。
- 引用他人观点一律**转述 + 注明出处**，不复制原文（这也是公开仓库的版权底线）。
- 每条笔记顶部带 `status`：活跃 / 归档 / 已过时。

### 4. 产物：没有产物的学习不算完成

这是六步里最容易被跳过、也最关键的一步。

产物不必大，可以是：

- 一段能跑的最小代码
- 一张自己画的结构图
- 一篇讲给别人听的文章
- 一个能复用的提示词或检查清单

**判据很简单：能不能给别人看。**能给别人看，说明你真的消化了；只能自己看，多半还停留在「我以为我懂了」。

### 5. 复盘：写下来「我哪里理解错了」

复盘不是总结成绩，是**抓错误**。

三个固定问题：

1. 学之前我以为是什么？现在改了什么？
2. 哪一步卡住了？为什么卡住？（是基础不够，还是输入源讲得不清楚？）
3. 下次同类内容，我会怎么学得更快？

第 2 问最有用——卡住的原因会重复出现，识别一次，省下以后十次。

### 6. 沉淀：把这次的方法存成卡片

每完成一条学习线，问一句：**这次学到的东西里，有没有一部分是「下次还能用」的？**

有，就写成一张方法卡，存进 [`cards/`](cards/)。没有，说明这次的经验是一次性的，记个结论就行。

这是整个循环的价值出口——**笔记会过时，方法不会**。

## 防断档机制

| 机制 | 做法 |
|------|------|
| **最小承诺** | 每天 25 分钟，不是 2 小时。状态好就多学，状态差就只做 25 分钟——**但不归零**。 |
| **绑定固定时段** | 通勤 / 午休 / 睡前，绑定已有习惯，不靠意志力。 |
| **公开承诺** | 把打卡放进公开仓库。被人看着，比自己盯着自己管用。 |
| **断档兜底** | 断了不等于失败。允许中断，但要求：**中断后第一次恢复，只做最小动作**（写一行日志也算）。 |
| **周更节奏** | 每周至少一次 commit / 一次打卡记录。断更一次容易，断第二次就再也接不上。 |

## 这套循环的已知短板

诚实列出来，也是方法的一部分：

- **对强实践类内容效果好，对纯记忆类内容效果一般**——背定义这件事，循环帮不上忙，只能靠重复。
- **依赖「能找到好输入源」**——输入源本身讲得混乱时，循环的第一步就卡住了。
- **产物环节容易被跳过**——尤其在工作忙的时候，我自己的完成率也不到七成，靠公开仓库的社交压力在补。
